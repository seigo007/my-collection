# マイ図鑑・コレクション

**Ver3.0版**

HTML・CSS・JavaScriptの復習と、初めてのSQLを組み合わせて作る実習用アプリです。
このフォルダ1つで独立して動きます。初期の作品・場所はすべて架空です。
各日の実習冊子を使い、コードの入力・穴埋め・練習問題に取り組みます。____などの空欄は冊子用です。
ソースへは、空欄を埋めた正しいコードを入力してください。

## 開発・実行の基本

1. このフォルダ全体をPCへ保存します。
2. ChromeまたはEdgeで `https://vscode.dev` を開き、「フォルダーを開く」でこのフォルダを開きます。
3. コードを書いたらCtrl+Sで保存します。
4. エクスプローラーで、ルートの `index.html` をダブルクリックして実行します。
5. 書き換えたら、アプリを表示しているブラウザを再読み込みします。

ターミナル・npm・Python・Live Serverは不要です。実行時に外部CDNは使いません。
`assets/vendor/sql-asm.js` を含め、このフォルダ全体の構成を保ちます。
実習中に止まったら、保存・再読み込み→冊子のヒント→TAへの相談の順に確認します。
各課題の期待結果と比べて確認し、分からない点はTAに相談してください。

## Day 2 — 固定6件で、SQLを初めて使う

SQL実験室は、本体と独立した固定6件の練習用DBです。自分のコレクションを変更しても、
問題の答えは変わりません。授業開始時は「練習DBを戻す」で6件へ戻します。
実験室を閉じる→再開では、練習中の変更を保持します。ページの再読み込み・ブラウザのタブを閉じる操作で
練習DBは初期化されるため、自分のSQLは `sql/exercises.sql` に保存します。
練習用DBの内容は「SQLiteを保存」のバックアップには入りません。

「.sqlファイルを読み込む」は、SQLエディタへ内容を入れる操作です。
ファイルとエディタは自動で同期しません。各問を1文ずつコピーして実行し、その直後に
SQLを `sql/exercises.sql` へコピーし、Ctrl+Sで保存します。終盤の5分は確認と持ち出しに使います。
エディタにあるSQLは上から実行されます。1問分だけにして「SQLを実行」を押すと確認しやすくなります。
途中でエラーになったとき、それ以前に成功した変更は練習DBに残ります。

TAの短い実演のあと、冊子の穴埋めから練習問題へ進みます。SELECT、WHERE、AND、ORDER BY、
追加・変更・削除を順番に使います。文字は半角の一重引用符、列の区切りは半角カンマ、文末は`;`です。
追加した行のidは、その都度SELECTで確認します。idが必ず7になるとは限りません。

## Day 3 — チェック・SQL・件数表示をつなぐ

1. `TODO D3-A` に、idが `recommendation-filter` のチェックボックスと、
   idが `filter-summary` の文章欄を作ります。
2. `TODO D3-B` に、changeイベントで再描画する処理を書きます。
3. `getRecommendationCondition()` に、イチオシのSQL条件を書きます。WHEREや`;`は入れません。
4. `updateFilterSummary(rows)` に、forとifでイチオシを数え、文章を表示する処理を書きます。

初期6件なら、チェックなしは「表示中 6件 / イチオシ 5件」、ありは「表示中 5件 / イチオシ 5件」。
件数表示は、全登録データではなく**今表示中の行**を数えます。検索や分類と組み合わせて確かめます。
テスト3・テスト4・テスト5の3件を登録し、おすすめ度をそれぞれ3・4・5にします。
「テスト」で検索したとき、OFFは3件/2件、ONは2件/2件になれば境界テストに成功です。
基準を発展で変える場合、ラベル・SQL条件・件数計算の3か所を一致させます。

## 保存する3種類

1. **ソース** — vscode.devでCtrl+S。HTML・CSS・JS・自分のSQLを保存します。
2. **SQLiteバックアップ** — 「SQLiteを保存」で `my-collection.db` をダウンロード。
   自分の保存先で回数や日付が分かる名前にします。別PCでは「SQLiteを読み込む」で復元します。
3. **公開用データ** — 「公開用データを書き出す」で `collection-data.js` を保存し、
   自分の `data/collection-data.js` と同名で置き換えます。

アプリはIndexedDBにも自動保存しますが、ブラウザのデータ削除・PCの初期化などで消える場合があります。
授業の終わりにはソース全体と.dbを持ち帰ります。家庭PCでは.dbを読み込んでから、公開JSを書き出します。
仮公開を終えたら、**最新のソース全体と.db**を次回授業へ持参してください。
ローカルfile://と公開URLは別のDBです。実習はローカルで行い、公開側の追加・削除テストは1件だけにします。
同じアプリを複数タブで編集すると表示が一致しないことがあるため、実習中は1タブで使います。

## 個人のGitHub Pagesへ公開

Day 1後の宿題で、本人のアカウントを作成して仮公開します。第3回は完成版へ更新します。
本人のPublicリポジトリ `my-collection` へ、このフォルダの**中身**をアップロードします。
リポジトリ直下に `index.html` を置き、Pagesは `main / (root)` を選びます。
外側のフォルダごと、またはZIPのままはアップロードしません。
公開URL例は `https://USER.github.io/my-collection/` です。
詳しい操作は宿題ガイドへ。アカウントやパスワードは共有せず、認証情報も提出しません。

GitHub Pagesはファイルの配信役で、SQLiteは利用者のブラウザ内で動きます。
他の人の端末とリアルタイムでデータを共有する仕組みではありません。
公開を変更するときは、公開用データの差し替えとGitHubへの再アップロードが必要です。
以前のブラウザ保存がある場合は、先にSQLiteバックアップを取り、ページを再読み込みしてから
「配布データに戻す」で公開用データを確認できます。

## 素材・基盤

公開できる自作の紹介文と教材同梱素材を使います。個人情報は入力しません。
表示にはtextContent、入力値を使うSQLにはパラメータ束縛を使用しています。
自分でコードに書くSQL条件だけを、アプリの条件としてつないでいます。
SQLite読み込みは10MB・5,000件まで。SQL実験室の結果表は先頭200件までです。
長い再帰クエリなど、大きな負荷のかかるSQLは扱いません。
